# Надёжность приёма скробблов

Живое состояние воспроизведения и зачёт прослушивания — разные операции.
`POST /api/scrobble` не отключает приём после 40 записей за час: короткие
прослушивания и переключения тоже создают записи. Начальная запись получает
0 XP. Зачёт и XP по-прежнему требуют подтверждённого времени, а отдельный
антифрод анализирует скорость и аномалии, включая исключённые из статистики
записи. Лимиты запросов, проверка ключей, банов и настройки приватности остаются
обязательными.

Смена трека непосредственно после периодического сигнала принимается для всех
источников. Ограничение повторных одинаковых сигналов остаётся; его результат
тоже записывается в диагностику подключения. Поиск дополнительных метаданных
для всех источников выполняется фоном и не держит очередь живых событий.

В ARQ `cloud_poll` ставит отдельную задачу `poll_cloud_user` на каждый аккаунт.
Стабильный идентификатор не допускает повторной постановки уже ожидающей или
работающей задачи. Результат не хранится, поэтому следующий период может снова
опросить аккаунт. Медленный ответ одного сервиса не отменяет весь пакет
аккаунтов по 25-секундному таймауту планировщика. Сетевые запросы Spotify,
Яндекса и SoundCloud в обычном опросе выполняются вне блокировки приёма;
блокируется только запись результата.

Расширение 1.5.1 проверяет статус JSON, а не только HTTP 200. Временные отказы
повторяются, настройки фильтрации и проблемы авторизации видны в его окне.
Общая последовательная отправка живых событий и повторов не позволяет
запоздалому запросу переключить сервер обратно на предыдущую песню. Очередь
содержит только свежие состояния; API не поддерживает восстановление полной
истории по старым периодическим сигналам. Остановленные вкладки перестают
повторно отправлять одну и ту же паузу.
Сервер также не заменяет свежий активный трек остановленным треком другой
вкладки/сервиса (`ignored_inactive`). Пауза самого текущего трека принимается.

Для применения нужны обновлённые API **и worker**, а также новая версия
расширения. Установленный вручную ZIP сам не обновляется; после обновления
нужно перезагрузить вкладки музыкальных сервисов. Успешный `/health` проверяет
БД/Redis, но не доказывает, что worker опрашивает подключённые сервисы.
