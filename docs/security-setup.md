# Настройка защиты: что делает владелец

Код сайта сам ограничивает частоту запросов, размер запросов, перебор паролей
и ключей, умеет блокировать адреса и спрашивать капчу. Но часть защиты
включается только снаружи: в аккаунтах, у хостера и в DNS. Ниже — по
порядку важности.

## 1. Двухфакторная защита аккаунтов

Кто войдёт в один из этих аккаунтов, получит сайт целиком, поэтому включите
вход с кодом из приложения (не по SMS) во всех:

- GitHub — Settings → Password and authentication;
- хостинг сервера;
- регистратор домена `vein.guru`;
- почта, к которой привязаны всё перечисленное (через неё восстанавливают пароли);
- Cloudflare и Yandex Cloud, если подключите их по пунктам ниже.

На сайте у администраторов вход с кодом обязателен (`ADMIN_REQUIRE_2FA=1`),
не выключайте это.

### Защита ветки на GitHub

Settings → Branches → Add branch ruleset для `VEIN`:

- Require a pull request before merging;
- Require status checks to pass (CI/CD Pipeline);
- Block force pushes, Restrict deletions.

Тогда даже с украденным паролем от GitHub нельзя тихо подменить код,
который сам выкатывается на сервер.

## 2. Защита от DDoS: Cloudflare перед сервером

Лимиты сайта спасают от одного злоумышленника, но не от тысяч адресов
сразу: такой поток забивает канал сервера раньше, чем доходит до кода.
Это решает прокси-сеть перед сервером. Ниже — для Cloudflare (бесплатный
тариф); DDoS-Guard настраивается похоже.

1. Зарегистрируйтесь на cloudflare.com, добавьте домен `vein.guru` и смените
   NS-серверы у регистратора на выданные Cloudflare.
2. В DNS у записей `music` и `api.music` включите оранжевое облако (Proxied).
3. SSL/TLS → Overview → режим **Full (strict)**.
4. На сервере:

   ```sh
   /opt/veinmusic/deploy/cloudflare.sh
   /opt/veinmusic/deploy/deploy.sh
   ```

   Скрипт записывает в `deploy/.env` сети Cloudflare. Без этого сайт видел
   бы вместо посетителей адреса Cloudflare: все делили бы один лимит
   запросов, а блокировка «плохого» адреса отрезала бы всех. Запускайте
   скрипт раз в несколько месяцев: Cloudflare изредка меняет сети.
5. **Закройте прямой доступ.** У хостера в панели (облачный файрвол /
   Security groups) разрешите входящие 80 и 443 только с адресов из
   https://www.cloudflare.com/ips/, а SSH (22) — только со своего адреса,
   если он постоянный. Без этого атакующий найдёт IP сервера (например, по
   старым DNS-записям) и пойдёт в обход Cloudflare. Именно в панели хостера,
   а не в `ufw`: Docker открывает порты в обход `ufw`.

Отключить: `deploy/cloudflare.sh --off` и `deploy/deploy.sh`.

## 3. Капча

Включается ключами в `deploy/.env` и спрашивается при регистрации и после
трёх неудачных попыток входа. Пока ключей нет, капчи нет.

Яндекс SmartCaptcha (надёжно работает из России):

1. console.yandex.cloud → SmartCaptcha → Создать капчу. В списке доменов —
   `music.vein.guru`.
2. Скопируйте ключ клиента и ключ сервера в `deploy/.env`:

   ```sh
   CAPTCHA_PROVIDER=yandex
   CAPTCHA_SITE_KEY=ключ клиента
   CAPTCHA_SECRET_KEY=ключ сервера
   ```

Cloudflare Turnstile: dash.cloudflare.com → Turnstile → Add widget, домен
`music.vein.guru`, затем `CAPTCHA_PROVIDER=turnstile` и два ключа.

Затем `deploy/deploy.sh`. Ключ сервера никому не показывайте.

## 4. Сервер

`deploy/setup-server.sh` уже ставит файрвол, fail2ban и автоматические
обновления безопасности. Отдельно стоит отключить вход по SSH-паролю:

1. С вашего компьютера: `ssh-copy-id root@адрес-сервера`, затем проверьте,
   что `ssh root@адрес-сервера` входит без пароля.
2. На сервере: `DISABLE_SSH_PASSWORD=1 /opt/veinmusic/deploy/setup-server.sh`.

Скрипт не выключит пароли, пока на сервере нет ни одного ключа.

## 5. Резервные копии

Ежедневные копии базы лежат на том же сервере: от потери сервера они не
спасут. Настройте внешние копии по `docs/offsite-backups.md` и один раз
проверьте восстановление из них. Копия, из которой ни разу не
восстанавливались, может оказаться пустой ровно тогда, когда понадобится.

## 6. Во время атаки: раздел «Безопасность» в админке

- Таблица отказов за час и за сутки: неудачные входы, неверные API-ключи,
  превышения лимита, капча. При превышении порога за час администраторы
  получают уведомление.
- Адреса с наибольшим числом отказов за час — с кнопкой «На сутки».
- Блокировка адреса или подсети на срок от часа до года.

Блокируйте адреса только против идущей атаки. За одним адресом бывают
сотни людей (мобильные операторы, офисы, общежития), адреса меняются, а
обходится блокировка включением VPN. Против конкретного человека
используйте блокировку аккаунта. Если аккаунт или сервер всё-таки
взломали, действуйте по `docs/incident-response.md`.
