## 🌟 О проекте

**VEIN Music** — независимая платформа для любителей музыки. Она собирает прослушивания из браузера, десктопных плееров и облачных сервисов, строит статистику и рекомендации, превращает прослушивание в игру с уровнями и достижениями, позволяет слушать музыку вместе с друзьями и даёт разработчикам открытый API.

## ⚡ Ключевые возможности

### 🎧 1. Сбор прослушиваний из любых источников
* **Браузерное расширение (Chrome, Edge, Яндекс Браузер и Firefox 109+, Manifest V3)**:
  * Считывает трек и прогресс воспроизведения на вкладках **Яндекс Музыки**, **Spotify**, **VK Музыки**, **YouTube Music**, **Apple Music** и **SoundCloud**.
  * **Офлайн-очередь**: если сервер недоступен, прослушивания сохраняются в хранилище расширения (до 500 штук) и досылаются раз в минуту через `chrome.alarms`.
  * **Подключение по коду**: расширение показывает короткий код, пользователь подтверждает его на странице `/link`, и расширение получает собственный ключ. Ключ можно отозвать в настройках.
* **Десктопный клиент (`desktop_client/`)**:
  * **Windows**: системные медиаэлементы управления (SMTC) и, как запасной вариант, чтение заголовков окон **Spotify**, **AIMP**, **foobar2000**, **VLC**, **VK** и **Яндекс Музыки**.
  * **Linux**: любые плееры с поддержкой MPRIS (через `playerctl`).
  * **Discord Rich Presence** с обложкой, названием трека, артистом и таймером.
  * Локальная очередь `~/.veinmusic/queue.json`, которая досылается при восстановлении сети.
* **Облачный скробблинг**: фоновый опрос того, что играет в **Spotify** и **Яндекс Музыке**, без открытых вкладок и плееров. Работает как задача воркера с распределённой блокировкой, поэтому опрос не дублируется при нескольких экземплярах сервера.
* **Экспорт во внешние сервисы**: каждое засчитанное прослушивание можно автоматически отправлять в **Last.fm**, **ListenBrainz** и **Libre.fm** (настраивается через API: `/api/developer/export/config`).
* **Импорт истории из Last.fm**: постраничный импорт в фоне с прогресс-баром. После сбоя импорт продолжается с той же страницы, а повторный запуск забирает только новые прослушивания.

---

### 🛡️ 2. Обработка прослушиваний и защита от накруток
* **Нормализация метаданных**: из названий убираются пометки вроде `Remastered`, `Live at …`, `Radio Edit`, `Deluxe Edition`, `Explicit`, а `feat.` переносится к артисту.
* **Засчитывание прослушиваний**: трек засчитывается и приносит XP, только если прослушано не меньше 85% его длительности. Повторные сигналы о том же треке обновляют одно прослушивание, а не создают дубли.
* **Ограничение частоты запросов** на скробблинг, вход и регистрацию. Счётчики общие для всех процессов (хранятся в Redis).
* **Антифрод**: система отмечает подозрительных пользователей по аномальному числу прослушиваний в час и в сутки и по потоку очень коротких треков. Администратор может сбросить им XP или снять отметку.
* **Чёрный список**: блокировка треков и артистов по ключевому слову, точному имени артиста или регулярному выражению.

---

### 📊 3. Статистика и рекомендации
* **Графики на Recharts**: активность по часам и дням недели, динамика прослушиваний; периоды — 7 дней, 30 дней, всё время.
* **Топы** артистов, треков и альбомов, любимые жанры.
* **Итоги за 30 дней (Wrapped)** в профиле и **OG-карточки итогов недели или месяца** для соцсетей.
* **Рекомендации** (`/api/recommendations/me`): треки из любимых жанров, новинки знакомых артистов и то, что популярно в сообществе.
* **Музыкальная совместимость**: процент совпадения вкусов с другим пользователем, общие артисты, подбор «музыкальных двойников» и поиск людей со схожим вкусом.
* **Настроение**: определение текущего музыкального настроения по последним трекам.

---

### 🏆 4. Геймификация, профиль и социальные функции
* **Уровни и ранги**: XP за каждое засчитанное прослушивание (x2 за любимые треки), ранги от *Туриста* до *Божества*, ежедневные серии прослушиваний. Администратор может включить множитель XP.
* **Рамки аватара**, которые открываются по уровню (Меломан, Аудиофил, Маньяк, Легенда, Божество), плюс рамки, созданные администратором.
* **Достижения**, которые администратор настраивает правилами: число прослушиваний, ночные прослушивания, конкретный трек, альбом или артист. О новых достижениях приходит уведомление на сайте и Web Push.
* **Оформление профиля**: аватар и обложка с обрезкой при загрузке, страна, ссылки на Telegram, GitHub и Instagram, свой акцентный цвет сайта.
* **Витрина профиля**: любимые артист, трек и альбом. Менять их можно раз в 30 дней.
* **Подписки и лента**: подписчики и подписки, лента друзей и глобальная лента с лайками и комментариями, фильтр ленты по источнику (Яндекс, Spotify, десктоп, расширение).
* **Лидерборд** слушателей по XP.
* **Слушать вместе**: комнаты на WebSockets, где ведущий (DJ) управляет воспроизведением, а остальные слушают синхронно и общаются в чате. Кто может зайти в комнату — все, только подписки или никто — решает сам пользователь.
* **Приватный профиль**: история и статистика скрыты от посторонних.

### 🛠️ 5. Виджеты, PWA и платформа для разработчиков
* **SVG-виджеты для README на GitHub и сайтов**:
  * `Now Playing` — что играет сейчас, с анимированным эквалайзером (`/api/widgets/now-playing/{username}.svg`);
  * `Top Artists` — топ-5 артистов (`/api/widgets/top-artists/{username}.svg`).
* **OG-карточки 1200×630** для соцсетей: итоги недели или месяца (`/api/widgets/og/recap/{username}.svg`) и полученные достижения (`/api/widgets/og/achievement/{username}/{id}.svg`).
* **PWA**: сайт можно установить на телефон или компьютер (Service Worker и `manifest.json`).
* **Web Push**: уведомления о новых достижениях (стандарт RFC 8291, ключи VAPID). Включаются во вкладке «Безопасность и данные».
* **API для разработчиков**:
  * Личные ключи (`vm_...`) с правами (scopes), хранятся в виде хэша PBKDF2-HMAC-SHA256.
  * Вебхуки на события `scrobble.created` и `achievement.unlocked` с подписью `X-VEIN-Signature` (HMAC-SHA256).
  * Справочник по API на странице `/developers`.
* **Умная ссылка** `/api/redirect`: открывает найденный трек в Яндекс Музыке.
* **Объявления и флаги функций**: баннер объявлений на сайте и включение функций без перевыпуска.

---

### 🔐 6. Безопасность и данные аккаунта
* **Сессии**: выход со всех устройств одной кнопкой; забаненный пользователь сразу теряет доступ во всех сессиях.
* **Защита входа**: пароль от 8 символов, блокировка на 15 минут после 10 неудачных попыток.
* **Шифрование**: OAuth-токены, сессионные ключи и секреты вебхуков хранятся в базе в зашифрованном виде.
* **Заголовки безопасности**: CSP, запрет встраивания во фреймы, `nosniff`, HSTS в продакшене.
* **Защита от SSRF**: вебхуки и push отправляются только на публичные адреса, с проверкой IP на момент отправки.
* **Мои данные**: выгрузка профиля, истории, подписок, комментариев и достижений в JSON и удаление аккаунта с подтверждением паролем.

---

### 🛡️ 7. Панель администратора (`/admin`)
* **Обзор**: метрики, состояние системы и аналитика, активные комнаты «Слушать вместе», очистка кэша, задачи импорта Last.fm с перезапуском.
* **Пользователи**: бан, роль, верификация, изменение уровня, сброс профиля, удаление прослушиваний или аккаунта, выдача и снятие достижений.
* **Антифрод**: список подозрительных пользователей, сброс XP, снятие отметки.
* **Каталог**: правила чёрного списка, слияние дубликатов, удаление треков.
* **Геймификация**: достижения, рамки аватара, множитель XP.
* **Объявления и флаги функций**.

```
               ┌────────────────────────────────────────────────────────┐
               │                    КЛИЕНТСКИЙ СЛОЙ                     │
               │ Next.js 16 (PWA) │ Расширение MV3 │ Desktop (Py/RPC)   │
               └───────────────────────────┬────────────────────────────┘
                                           │ HTTPS / WebSockets
                                           ▼
               ┌────────────────────────────────────────────────────────┐
               │                     FASTAPI SERVER                     │
               │  Auth / API / WebSockets / Антифрод / Рекомендации      │
               └───────────────┬────────────────────────┬───────────────┘
                               │                        │
                    PostgreSQL │                        │ Redis / ARQ
        ┌──────────────────────▼───────┐        ┌───────▼────────────────────────┐
        │  Пользователи, прослушивания │        │  Кэш, лимиты, WebSocket-комнаты│
        │  каталог, вебхуки (Alembic)  │        │  Воркер: достижения, вебхуки,  │
        │                              │        │  экспорт, импорт, опрос облака │
        └──────────────────────────────┘        └────────────────────────────────┘
```

* **Backend**: Python 3.11, **FastAPI**, SQLAlchemy 2.0, Alembic, PostgreSQL, Redis, ARQ, Pydantic v2, cryptography, PyJWT, Sentry (опционально).
* **Frontend**: **Next.js 16** (App Router, React 19), TypeScript 6, Tailwind CSS 4, Framer Motion, Recharts, Lucide.
* **Desktop**: Python 3, WinRT (Windows SMTC), `playerctl`/MPRIS (Linux), Discord IPC.
* **Расширение**: JavaScript, Chrome Extensions API (Manifest V3), совместимо с Firefox.
* **CI/CD и качество**: GitHub Actions (тесты на SQLite и PostgreSQL, проверка миграций), ruff, flake8, mypy, bandit, ESLint 9, Prettier, Playwright E2E, CodeQL, SonarQube Cloud, GitGuardian, Dependabot.

## 🚀 Быстрый старт

### 1. Клонирование репозитория
```bash
git clone https://github.com/Peaostrel/VEINMusic.git
cd VEINMusic
```

### 2. Настройка окружения
```bash
cp .env.example .env
# Обязательно задайте SECRET_KEY, POSTGRES_PASSWORD и REDIS_PASSWORD
```

### 3. Запуск всего стека в Docker (продакшен)
```bash
docker compose up -d --build
```
Поднимаются PostgreSQL, Redis, API (миграции применяются автоматически при старте),
фоновый воркер arq (достижения, вебхуки, экспорт скробблов, импорт Last.fm,
опрос Spotify/Яндекса, ночная очистка неиспользуемых загрузок) и фронтенд.
Проверка состояния: `GET /health`.

**Резервные копии.** Сервис `db-backup` раз в сутки делает `pg_dump` в том
`db_backups` и хранит копии `BACKUP_KEEP_DAYS` дней (по умолчанию 7).
Восстановление:
```bash
docker compose exec db-backup ls /backups
docker compose exec -T db-backup pg_restore --clean --if-exists \
  -d veinmusic /backups/<файл>.dump
```
Копии лежат на том же сервере: для защиты от потери диска периодически
забирайте их на другое хранилище.

### 3а. Локальная разработка без Docker для кода
Для работы по обычному http поставьте в `.env` значение `ENVIRONMENT=development`
(в продакшене должно оставаться `production`).
```bash
# Только базы данных
docker compose up -d db redis

pip install -r requirements.txt
python -m app.core.migrate          # миграции (подхватывает и старые базы без истории Alembic)

uvicorn app.main:app --reload --port 8000
arq app.worker.WorkerSettings       # фоновый воркер (в отдельном терминале)
```
Web Push включается ключами VAPID: `python -m app.services.push_notifications`
выведет пару ключей для `.env`.

### 4. Настройка и запуск фронтенда
```bash
cd frontend
npm install
npm run dev
```
Фронтенд будет доступен по адресу: `http://localhost:3000`.

### 5. Запуск нативного десктопного клиента (Опционально)
```bash
cd desktop_client
pip install -r requirements.txt
python -m desktop_client.main
```

### 6. Установка браузерного расширения
1. Откройте любой Chromium-браузер (Chrome, Edge, Яндекс Браузер, Brave).
2. Перейдите в `chrome://extensions/` и включите **«Режим разработчика»** (Developer Mode).
3. Нажмите **«Загрузить распакованное расширение»** (Load unpacked) и укажите папку `music-extension`.
4. В окне расширения нажмите **«Подключить через сайт»** и подтвердите код на странице `/link`.
   Расширение получит собственный ключ, который можно отозвать в настройках
   («Безопасность и данные»).

В **Firefox** (109+) откройте `about:debugging` → «Этот Firefox» → «Загрузить временное
дополнение» и выберите файл `music-extension/manifest.json`.

## 🧪 Тестирование и проверка качества

```bash
# Юнит- и интеграционные тесты бэкенда (SQLite)
pytest

# Те же тесты на PostgreSQL и с реальным Redis (как в CI)
TEST_DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/veinmusic_test \
TEST_REDIS_URL=redis://localhost:6379 pytest

# Проверка, что миграции совпадают с моделями
alembic check

# Проверка типизации и линтинга бэкенда
flake8 app tests desktop_client
mypy app/

# Проверка линтера и форматирования фронтенда
cd frontend
npm run lint
npm run format:check
npm run build
```
